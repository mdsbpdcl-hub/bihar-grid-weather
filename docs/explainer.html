Technical Explainer

Bihar Grid & Weather Dashboard

A Google Apps Script system that joins circle-level outages from the Daily Outage Analytics sheet and supply complaints from the 1912 call centre with weather for all 38 districts. It flags circles hit beyond normal, predicts today's and tomorrow's outages and complaints, emails a morning alert and serves an interactive web page with a PDF report.

How the Pieces Fit

System Architecture

Three inputs, one script, four outputs. Everything lives in Google's cloud: no server, database or paid service.

The script Code.gs is bound to the Bihar Grid Weather Archive sheet (the main sheet). Every morning a time trigger runs runDaily(), which reads the two source sheets (read only), fetches weather, works out status and predictions, writes everything to the main sheet and the Drive folder, and emails the alert. D

The page Index.html is served by the same project as a web app. It gets the grid figures through google.script.run.getFeed() and fetches weather straight from Open-Meteo in the browser, so live weather never waits on the script. D

Apps Script is Google's JavaScript runtime attached to Sheets, Drive and Gmail. A trigger runs a function on a schedule; a web app deployment gives a URL that runs doGet() and returns a page or data. B

Process Lifecycle

Daily Run

runDaily() fires once a day between 9 and 10 AM IST, after both source sheets refresh. Each step runs inside step_(), so one failure is logged and the rest still run. D

Source Check checkSources_()
Confirms yesterday's outage data has arrived for all 20 circles, circle totals equal the division sums, and complaints match the 1912 sheet. Problems go to the Run Log and a red line at the top of the email.
Weather updateWeather_(3)
One Open-Meteo call for 38 districts. Past days go to Weather History (upsert by date + circle); today and the next two days replace Weather Forecast.
Grid Archive archiveGrid_()
Copies Weather Link rows into Grid History. Days older than Weather Link's 14 are filled from division totals with complaints left blank; an earlier complaint figure is never overwritten by a blank.
Division Archive archiveDivisions_()
Copies both History Divisions tabs into Division History (key: date + discom + circle + division).
Thresholds computeThresholds_()
Works out each circle's normal and, once 30 days of history exist, learns its own rain limit. Writes Circle Thresholds.
Prediction predict_()
Refits the model on all history, predicts the next two days per circle, writes Model and Predictions, then fills in actuals for earlier predictions.
Drive Archive archiveToDrive_(false)
Re-saves the last 3 days to the archive tabs and writes one JSON file per day under JSON/yyyy/yyyy-mm/ in the WeatherPrediction folder.
Cache Clear
Removes the cached feed so the page shows the new figures at once.
Alert sendAlert_()
Emails the summary: data check, prediction for today, circles beyond weather, weather-driven circles and circles at risk in the next 48 hours.

Setup

setup() is run once by hand. It creates all tabs, copies any history the old script kept in the outage sheet, backfills 92 days of weather, runs every step once, saves the full Drive archive and creates the 9 AM trigger (deleting any older one). Running it again is safe. D

Some models run fewer than 7 days. A model with no value for a day is left out of that day's median, so later days may show "5 of 5 models". This is expected, not a fault. D To confirm all six are live, run checkWeatherModels(); it logs one line per model with days returned for each variable.

Rain figures are model estimates, averaged over each circle's districts, not rain-gauge readings. The page forecast (six-model median) and the script's risk list (best match) can differ slightly. For warnings follow IMD Patna. D
Core Logic

Circle Status

Every circle-day gets one of three labels by comparing the circle with its own normal, so a rural circle and PESU West can be judged on the same scale. D

Beyond Weather

Outages or complaints at 1.8× normal or more without heavy rain or strong gusts. Check the network.

Weather-Driven

The same rise with rain at or above the circle's limit (that day or the day before) or gusts of 45 km/h or more.

Normal

Both measures below 1.8× normal.

Calculation

// status_(): one circle, one day
normalOut  = median(outage min per feeder, 28 days either side, excluding the day)
normalCmp  = median(complaints, same window)
ro = outage per feeder ÷ normalOut      rc = complaints ÷ normalCmp
rain = max(rain that day, rain day before)
stress = rain ≥ circle limit  OR  gust ≥ 45
status = max(ro, rc) ≥ 1.8 ? (stress ? 'W' : 'B') : 'N'

Rain Limit Learning

Each circle starts on 15 mm. After 30 days of grid history, computeThresholds_() takes its dry-day normal (days where rain that day and the day before was under 5 mm), groups rainy days into bands of 5, 15, 25, 40 and 60 mm, and picks the lowest band where at least 3 days had a median outage of 1.8× normal or more. That becomes the circle's own limit, marked "Learned". D

A weak network shows up as a lower learned limit: a circle that trips at 5 mm will be flagged at risk for lighter forecast rain than one that holds up to 25 mm.
Forecasting

Prediction Model

A statistical regression, not a language model or neural network. Every morning it learns from all past circle-days how weather and yesterday's level move a circle away from its normal, then applies that to the forecast. D

Method

Target. The model predicts the level: ln(value ÷ normal), where normal is the circle's median over the last 60 days (dry days if at least 7). Level 0 is a normal day; ln 2 ≈ 0.69 is double. Logs turn multiplying effects into adding ones. D

Fitting. ridge_() solves least squares with a small penalty (λ = 1) on every weight except the intercept, by Gaussian elimination with partial pivoting. All 20 circles are pooled, so the model has 20 examples per day of history. D Ridge regression shrinks weights toward zero, which keeps them steady when examples are few and features move together, as rain on consecutive days does. B

Safeguards. fitModel_() refits with any negative weather weight set to zero, most negative first, because rain, gusts and heat cannot reduce outages. Below 40 training rows the script skips the model and assumes half of yesterday's excess carries over. D

Range. The residual spread (floor 0.15) gives an 80% band: level ± 1.2816 × spread. Tomorrow's band is 25% wider. Statewide totals add circle bands in quadrature (square root of the sum of squares). D

Risk. High at 1.8× normal or more, Medium at 1.3×, otherwise Normal. Scoring: next morning each prediction gets its actual figure and an "in range" Yes/No; the page's track record uses the last 30 days. D

Prediction Calculator

Weights fitted on history to 31 Oct (outage model). The script refits every morning; the Model tab holds the current values. D

The model sees only weather, Sunday and yesterday's level. Planned shutdowns, upstream grid trips, festival load and feeder condition are invisible to it, so a day like 21 Oct (2.4× the calm-day level with no rain) will be missed and correctly marked Beyond Weather. The page shows "Learning" until about 60 days of history.
Storage

Sheets & Tabs

The main sheet holds eight working tabs the script maintains and five archive tabs meant for people. All writes go through upsert_(): rows are matched by their key columns, replaced if present, added if new, duplicates collapsed and the tab kept sorted. D

Drive Archive

Folder WeatherPrediction → JSON/2026/2026-10/2026-10-31.json: one fixed record per day with circles, divisions, and for the latest day the forecast and predictions as issued. Only the latest file is overwritten on a normal run. D

Front End

Page Code

Index.html is one file: HTML layout, CSS and plain JavaScript, with no framework. Charts and maps are SVG strings built in code; the PDF uses jsPDF and its table plug-in, loaded from a CDN only when Export PDF is pressed. D

State

One object S holds the tab, district, scope (gDis), days, selected day, weather and feed. Every change calls renderAll(), which redraws only the active tab.

Scope

inScope(circle, discom) decides what every view includes: Bihar, SBPDCL, NBPDCL or D:<district> (the circles covering that district).

District Pick

pickDist() sets the district scope and loads its weather; pickAll() returns to All Districts. A request counter ignores a slow reply for an earlier pick.

Memory

The last district is kept in browser storage, inside try/catch, so the page opens where it was left.

Discrepancies

Known Gaps

1
Two Different Normals. Status and the circle table use a rolling 28-day median of all days (status_); KPI tiles, chart ratios and predictions use a 60-day median of dry days (normals_). On 31 Oct, with Gaya selected, the Overview tile read 1.8× while the circle table showed Gaya Ji at 1.4×. Both are valid; they answer slightly different questions. D
2
Status of Older Days Shifts. The 28-day window looks both ways, so a past day's ratio changes as later days arrive. The Drive JSON for each day is frozen once it falls out of the 3-day redo window. D
3
Complaints for 14 Days Only. Weather Link covers the 14 days the 1912 sheet has by circle. Earlier grid days (13–17 Oct) have outages but no complaints, so the complaint model trains on fewer rows. D
4
History Days Is Approximate. The "Learning · n days" badge is training rows ÷ 20 circles, not a calendar count. D
5
Late Source Data. If the outage sheet has not refreshed by the run, "today" is predicted from the day before yesterday. The Source Check now flags this in the email. D
6
One-District Weather Detail. With All Districts selected, the Weather tab's detailed forecast stays on the last district picked (Patna to start); the rain map and Overview card cover all of Bihar. D
